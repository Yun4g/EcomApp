Great question — this is exactly how real-world backends protect routes 🔐
I’ll show you a clean, production-style RBAC (Role-Based Access Control) setup using Node.js + Express + TypeScript.

🧠 Concept (Simple)

You want to:

Authenticate user (who are you?) → via JWT
Authorize user (are you allowed?) → via roles/permissions

That error:

{"status":"fail","message":"You do not have permission to perform this action."}

comes from the authorization layer.

1️⃣ Define Roles (TypeScript way)
// types/roles.ts
export enum Role {
  APPLICANT = "APPLICANT",
  ADMIN = "ADMIN",
  STAFF = "STAFF",
}
2️⃣ Extend Express Request (VERY IMPORTANT)
// types/express.d.ts
import { Role } from "./roles";

declare global {
  namespace Express {
    interface UserPayload {
      id: string;
      role: Role;
    }

    interface Request {
      user?: UserPayload;
    }
  }
}
3️⃣ Authentication Middleware (JWT)

This checks if the user is logged in.

// middleware/auth.middleware.ts
import { Request, Response, NextFunction } from "express";
import jwt from "jsonwebtoken";

export const protect = (
  req: Request,
  res: Response,
  next: NextFunction
) => {
  const token = req.headers.authorization?.split(" ")[1];

  if (!token) {
    return res.status(401).json({
      status: "fail",
      message: "Not authorized, no token",
    });
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET!) as any;

    req.user = {
      id: decoded.id,
      role: decoded.role,
    };

    next();
  } catch (err) {
    return res.status(401).json({
      status: "fail",
      message: "Invalid token",
    });
  }
};
4️⃣ Role-Based Authorization Middleware 🔥

This is where your error message comes from.

// middleware/role.middleware.ts
import { Request, Response, NextFunction } from "express";
import { Role } from "../types/roles";

export const restrictTo = (...allowedRoles: Role[]) => {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!req.user) {
      return res.status(401).json({
        status: "fail",
        message: "Not authenticated",
      });
    }

    if (!allowedRoles.includes(req.user.role)) {
      return res.status(403).json({
        status: "fail",
        message: "You do not have permission to perform this action.",
      });
    }

    next();
  };
};
5️⃣ Use It in Routes 🚀
import express from "express";
import { protect } from "../middleware/auth.middleware";
import { restrictTo } from "../middleware/role.middleware";
import { Role } from "../types/roles";

const router = express.Router();

// Only ADMIN can access
router.get(
  "/admin-dashboard",
  protect,
  restrictTo(Role.ADMIN),
  (req, res) => {
    res.json({ message: "Welcome Admin!" });
  }
);

// ADMIN + STAFF
router.post(
  "/create-post",
  protect,
  restrictTo(Role.ADMIN, Role.STAFF),
  (req, res) => {
    res.json({ message: "Post created" });
  }
);

// All authenticated users
router.get("/profile", protect, (req, res) => {
  res.json({ user: req.user });
});

export default router;
⚡ Example Flow
User logs in → gets JWT:
{
  "id": "123",
  "role": "APPLICANT"
}
User hits:
GET /admin-dashboard
Middleware checks:
✅ Logged in → OK
❌ Role not ADMIN → returns:
{
  "status": "fail",
  "message": "You do not have permission to perform this action."
}
💡 Pro Tips (Real-world)
Store roles in DB (like your user object)
Add permissions later (e.g. canCreateUser)
Use constants/enums — never hardcode strings
Keep middleware reusable (like we did)
🔥 Bonus (Advanced idea)

Instead of roles, you can do:

restrictTo("CREATE_USER", "DELETE_USER")

That’s permission-based access control (PBAC) — more flexible.
